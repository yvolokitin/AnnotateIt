# SAM Mobile Integration in AnnotateIt

This document explains how Segment Anything (SAM) aka MobileSAM is integrated into the AnnotateIt Flutter project, the runtime pathways across platforms, and how we support both segmentation (polygons) and detection (bounding boxes) with the same SAM tool.

## Overview

- Single-click prompt: The user clicks a point on the image using the SAM tool. The app computes a segmentation mask around the clicked region and converts it into a polygon.
- Cross‑platform behavior:
  - Web: Real MobileSAM ONNX encoder/decoder inference through onnxruntime‑web (via a small JS FFI bridge).
  - Windows/macOS/Android/iOS: A high‑quality heuristic fallback (seeded region growing + contour extraction) that produces consistent polygons without bundling native ONNX runtimes.
- Detection support: In detection projects, the resulting polygon is automatically converted to a tight bounding box and saved as annotationType="bbox".

## Key Files

- Services (Flutter/Dart):
  - lib/services/sam_segmentation_service.dart
    - Public API: `initialize()`, `close()`, `generateMaskPolygon(...)`.
    - On Web, it invokes `samInit(...)` and `samRun(...)` to run MobileSAM encoder/decoder via JS.
    - On non‑Web, falls back to content‑aware region growing; the API contract stays the same.
  - lib/services/sam_web_ffi.dart, lib/services/sam_web_ffi_web.dart, lib/services/sam_web_ffi_stub.dart
    - Platform FFI shims. The "web" version binds to JS, the stub returns false/empty on other platforms.
- Web bridge:
  - web/sam_inference.js — Loads onnxruntime‑web, MobileSAM encoder/decoder models, and exposes `window.SAM.init/run` used by the Dart FFI layer.
- Models:
  - assets/models_sam/mobile_sam.encoder.onnx
  - assets/models_sam/mobile_sam.decoder.onnx
  - assets/models_sam/models.ts — metadata and references for models.
- UI / Flow:
  - lib/widgets/imageannotator/annotator_left_toolbar.dart — Shows the SAM tool button for both segmentation and detection projects.
  - lib/widgets/imageannotator/annotator_canvas.dart — Emits click coordinates (image space) to the page when SAM is active.
  - lib/pages/annotator_page.dart — Calls `SamSegmentationService.generateMaskPolygon(...)` and creates either a polygon (segmentation) or a bounding box (detection) annotation.

## Runtime Pathways

1) Web (Chrome/Edge/Safari/Firefox)
- Initialization
  - `SamSegmentationService.initialize()` calls `samInit(...)` with encoder/decoder URLs:
    - `assets/assets/models_sam/mobile_sam.encoder.onnx`
    - `assets/assets/models_sam/mobile_sam.decoder.onnx`
  - The web/JS side loads the models via onnxruntime‑web.
- Inference
  - On click, we preprocess the image to 1024×1024 (NCHW float32, SAM mean/std normalization), run the encoder/decoder, and get a 256×256 mask. We upsample/contour via marching squares and simplify the polygon.

2) Windows/macOS/Android/iOS (Flutter) — Heuristic Fallback
- Initialization
  - `SamSegmentationService.initialize()` uses a stub for `samInit`. No native ONNX runtime is required.
- Inference
  - On click, `generateMaskPolygon(...)` performs:
    - Read RGBA pixels from the ui.Image.
    - Seeded region growing around the tap point with dynamic thresholds.
    - Marching squares for contour extraction.
    - Ramer–Douglas–Peucker (RDP) simplification.
  - This produces a high‑quality polygon mask consistent with the Web mode.

The API is identical across platforms. If/when you add native onnxruntime bindings for desktop/mobile, only the service internals need to change — the UI and page code can remain unchanged.

## Detection (Bounding Box) Support

- The SAM button is shown for both segmentation and detection projects.
- For detection projects, the polygon generated by SAM is converted into a tight bounding box and saved as `annotationType: 'bbox'`.
- Conversion is performed in lib/pages/annotator_page.dart inside `_handleSamTap(...)`:
  - Compute minX, minY, maxX, maxY across polygon points.
  - Clamp to image bounds; store Rect as `{x, y, width, height}`.

This provides a convenient "SAM‑powered detection" workflow: click to get a mask; we store its box.

## Why Polygon First?

- Using a polygon as the primary output gives the best of both worlds:
  - Segmentation projects: keep the high‑detail shape.
  - Detection projects: derive a tight box reliably from the same mask.
- The single SAM tool delivers both project types with minimal UI complexity.

## Model Preprocessing Details

- Image is resized to fit within 1024×1024 while preserving aspect ratio.
- Channels: RGB float32, normalized with SAM/MobileSAM mean/std:
  - mean = [123.675, 116.28, 103.53]
  - std  = [58.395, 57.12, 57.375]
- For Web SAM, decoder outputs 256×256; we upsample logically by step=4 for marching squares.

## File/Code References

- Service entry: `SamSegmentationService.generateMaskPolygon(...)`
- Toolbar: `AnnotatorLeftToolbar` — shows SAM for both detection and segmentation projects.
- Event flow: `AnnotatorCanvas` (emits tap) → `AnnotatorPage._handleSamTap` (creates polygon or bbox annotation).

## Platform Availability

- Web: Yes — Real MobileSAM inference via onnxruntime‑web (no server).
- Windows/macOS: Yes — Fallback heuristic segmentation implemented in Dart. Switchable to real runtimes later.
- Android/iOS: Yes — Fallback heuristic segmentation implemented in Dart. Can adopt on‑device ONNX later.

In all cases, the SAM tool works. The difference is the inference backend (real ONNX on web vs. heuristic fallback elsewhere), which is abstracted by the service.

## Performance & Limitations

- Web performance depends on browser WebGL/WebGPU capabilities. onnxruntime‑web uses WebGL by default.
- Fallback segmentation on mobile/desktop is CPU‑bound; for large images it may take noticeable time. Consider downscaling images for faster response if needed.
- If you introduce native ONNX runtimes later, wire them into `SamSegmentationService` to replace the fallback on those platforms.

## Adding/Updating Models

- Place MobileSAM ONNX files under `assets/models_sam/` and ensure they are declared in `pubspec.yaml` (already included).
- Update `web/sam_inference.js` and the URLs in `SamSegmentationService.initialize()` if you rename files.

## Developer Notes

- The service returns polygons in image coordinates; the UI converts them to annotations.
- Detection projects automatically convert SAM polygons to bounding boxes in `_handleSamTap(...)`.
- The UI reflects processing states (spinner on SAM button) via `isProcessingSAM`.

## Troubleshooting

- Web models not loading:
  - Check network paths: they are referenced as `assets/assets/models_sam/...` (Flutter web asset prefix + project assets path).
  - Open devtools console for errors from onnxruntime‑web.
- Mobile/Desktop too slow:
  - Consider pre‑resizing images or throttling clicks.
- Bounding box looks too big/small:
  - The bbox is the tight extents of the SAM polygon; if needed, add a small padding before saving (not enabled by default).
